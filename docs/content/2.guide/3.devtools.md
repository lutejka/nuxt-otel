When devtools are enabled (`devtools: true` in `nuxtOtel` config), the module adds an **OpenTelemetry** panel to [Vite DevTools](https://devtools.vite.dev) for browsing traces, logs, and metrics in real time. It is powered by [`vite-opentelemetry-inspector`](https://github.com/lutejka/vite-opentelemetry-inspector).

## Browse traces as waterfalls

**Traces** shows a resizable split panel with a trace list on the left and a waterfall timeline with span details on the right.

## Browse structured logs

**Logs** provides a scrollable list of log entries with severity badges and expandable metadata.

:zoomable-color-mode-image{alt="Logs view expandable log entries with severity badges" class="w-full rounded-lg border border-muted" dark="/images/logs-dark.png" light="/images/logs-light.png" width="1920" height="1080" loading="lazy"}

## Track metrics

**Metrics** shows one tile per metric with its latest value, a sparkline, and a histogram chart. Histograms are displayed as their average (`sum / count`), so recording a histogram of order quantities reads as the average order quantity. See [`useOtelMeter`](/guide/composables#record-metrics-with-useotelmeter) for recording custom metrics.

## Forward custom instrumentation to DevTools

When using a custom instrumentation setup (i.e. `instrument: false`), you can still forward spans, logs, and metrics to the DevTools panel. Point your exporter at the ingest endpoint:

```text
OTEL_EXPORTER_OTLP_ENDPOINT={devServerUrl}/__opentelemetry-ingest
```

The OTLP HTTP exporter appends the signal path, so traces go to `{devServerUrl}/__opentelemetry-ingest/v1/traces`, logs to `/v1/logs`, and metrics to `/v1/metrics`. You can also use those full URLs directly.

The panel is available in development only. Production builds export through the OTLP configuration you provide to the SDK.
