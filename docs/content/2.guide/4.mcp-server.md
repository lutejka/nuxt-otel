The OpenTelemetry panel exposes agent tools over the devframe MCP adapter provided by [`vite-opentelemetry-inspector`](https://github.com/lutejka/vite-opentelemetry-inspector#mcp).

::caution
The MCP integration is development-only. The OTEL tools query in-memory trace, log, and metric stores that are populated during development. In production builds, the OTEL-specific tools are not available.
::

## Install the MCP adapter

The MCP endpoint is only mounted when the optional `@devframes/agentic` peer is installed. Without it, devframe logs `DF0078`, serves no MCP endpoint, and the terminal shows `MCP server → disabled`.

::code-group

```bash [pnpm]
pnpm add -D @devframes/agentic
```

```bash [npm]
npm install -D @devframes/agentic
```

```bash [yarn]
yarn add -D @devframes/agentic
```

```bash [bun]
bun add -D @devframes/agentic
```

::

## Find your MCP endpoint

Start the dev server with DevTools enabled (`nuxtOtel.devtools: true`):

```bash [Terminal]
pnpm dev
```

Look for the `Nuxt OTel devtools` box in the terminal. The MCP server line shows your endpoint, derived from the dev server URL plus the devframe base path:

```bash [Terminal]
Nuxt OTel devtools:
  OTLP HTTP ingest  → http://localhost:3000/__opentelemetry-ingest
  MCP server        → http://localhost:3000/__opentelemetry/__mcp
```

## Connect an agent to the endpoint

Point your MCP client at the `__mcp` URL as a remote server. Devframe rejects requests without a matching `Origin` header, so always set `Origin` to your dev server origin.

```json [mcp.json]
{
  "mcp": {
    "nuxt-otel": {
      "type": "remote",
      "url": "http://localhost:3000/__opentelemetry/__mcp",
      "headers": {
        "Origin": "http://localhost:3000"
      },
      "enabled": true
    }
  }
}
```

::tip
If your dev server runs on a different port or host, update both `url` and the `Origin` header to match it — for example `http://localhost:3001`.
::

## Use available tools

| Tool            | Description                                                 |
| --------------- | ----------------------------------------------------------- |
| `get-traces`    | Retrieve all collected OpenTelemetry traces                 |
| `get-trace`     | Retrieve a single trace and its spans by `trace_id`         |
| `get-spans`     | Retrieve collected spans, optionally filtered by `trace_id` |
| `get-logs`      | Retrieve all collected OpenTelemetry logs                   |
| `get-metrics`   | Retrieve collected OpenTelemetry metric data points         |
| `clear-traces`  | Clear all collected traces and spans                        |
| `clear-logs`    | Clear all collected logs                                    |
| `clear-metrics` | Clear all collected metric data points                      |

## Fix connection problems

- **Endpoint shows `disabled`** — Install `@devframes/agentic` as a dev dependency and restart the dev server.
- **Request rejected or forbidden** — Set the `Origin` header to your exact dev server origin (scheme + host + port).
- **Empty traces, logs, or metrics** – Load a page in the browser first so the in-memory stores are populated, then query again.
