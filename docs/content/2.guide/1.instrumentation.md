Nuxt OTel can create spans with its built-in Node.js SDK or with an SDK you provide yourself.

## Use the built-in SDK on Node.js

When `nuxtOtel.instrument` is `true` (the default), the module adds a `NodeSDK` instance from `@opentelemetry/sdk-node`. It is designed for Node.js presets (`node-server`, `bun`, or the default Nitro preset) and exports telemetry via OTLP.

::note
The module currently loads the Node.js preset whenever `instrument` is enabled, regardless of your Nitro preset. On other presets, set `instrument: false` and use the custom setup below.
::

Configure the SDK with [OpenTelemetry environment variables](https://opentelemetry.io/docs/specs/otel/configuration/sdk-environment-variables/):

| Variable                       | Description                                                |
| ------------------------------ | ---------------------------------------------------------- |
| `OTEL_SERVICE_NAME`            | Service name reported by the SDK                           |
| `OTEL_TRACES_EXPORTER`         | Trace exporter (`otlp`, `console`, `none`)                 |
| `OTEL_METRICS_EXPORTER`        | Metrics exporter (`otlp`, `console`, `prometheus`, `none`) |
| `OTEL_LOGS_EXPORTER`           | Logs exporter (`otlp`, `console`, `none`)                  |
| `OTEL_EXPORTER_OTLP_ENDPOINT`  | Collector base URL; the SDK appends the signal path        |
| `OTEL_EXPORTER_OTLP_HEADERS`   | Headers sent to the collector, such as authorization       |

For example:

```bash [Terminal]
OTEL_SERVICE_NAME=my-nuxt-app OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318 pnpm dev
```

## Add custom instrumentation

For other presets, or when you need full control, disable the built-in setup:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nuxtOtel: {
    instrument: false,
  },
})
```

Install the OpenTelemetry packages used by the example:

::code-group

```bash [pnpm]
pnpm add @opentelemetry/sdk-node @opentelemetry/exporter-trace-otlp-http @opentelemetry/resources @opentelemetry/semantic-conventions
```

```bash [npm]
npm install @opentelemetry/sdk-node @opentelemetry/exporter-trace-otlp-http @opentelemetry/resources @opentelemetry/semantic-conventions
```

```bash [yarn]
yarn add @opentelemetry/sdk-node @opentelemetry/exporter-trace-otlp-http @opentelemetry/resources @opentelemetry/semantic-conventions
```

```bash [bun]
bun add @opentelemetry/sdk-node @opentelemetry/exporter-trace-otlp-http @opentelemetry/resources @opentelemetry/semantic-conventions
```

::

Then register the SDK in a Nitro plugin:

```ts [server/plugins/otel.ts]
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http'
import { resourceFromAttributes } from '@opentelemetry/resources'
import { NodeSDK } from '@opentelemetry/sdk-node'
import { ATTR_SERVICE_NAME } from '@opentelemetry/semantic-conventions'
import { defineNitroPlugin } from 'nitropack/runtime'

export default defineNitroPlugin((nitroApp) => {
  const sdk = new NodeSDK({
    resource: resourceFromAttributes({
      [ATTR_SERVICE_NAME]: 'my-nuxt-app',
    }),
    traceExporter: new OTLPTraceExporter({
      url: 'http://my-collector:4318/v1/traces',
    }),
  })

  sdk.start()

  // Flush buffered telemetry when the server shuts down.
  nitroApp.hooks.hook('close', () => sdk.shutdown())
})
```

You can use any exporter (Console, Jaeger, Zipkin) or add auto-instrumentations like `@opentelemetry/instrumentation-http`. The SDK reads the same `OTEL_*` environment variables, so you can keep exporter configuration outside the code.
