Nuxt OTEL gives you automatic OpenTelemetry tracing for Nuxt applications, built on Node.js Diagnostic Channels.

## What is Nuxt OTEL?

Nuxt OTEL hooks into Nuxt internals with Diagnostic Channels and creates real OpenTelemetry spans for renders, H3 requests, server routes and storage operations. You get deep observability with zero application code changes.

::note
This documentation includes AI integration with an MCP server and automatic `llms.txt` generation.
::

## What you can do

- **Trace renders automatically** — See SSR renders, islands, data fetches and plugin init as spans
- **Inspect requests end to end** — Follow an H3 request through srvx middleware into your handler and unstorage calls
- **Browse traces in DevTools** — Use the Vite DevTools OpenTelemetry panel with waterfall timeline and log viewer
- **Query traces from agents** — Let coding agents call `get-traces`, `get-spans` and `get-logs` during development
- **Export to any backend** — Ship OTLP to Jaeger, Zipkin, Grafana Tempo or any collector

## When to use Nuxt OTEL

Use Nuxt OTEL when you need to:

- Understand slow SSR renders or waterfall data fetching
- Debug server routes, middleware ordering and storage cache behavior
- Add OpenTelemetry without hand-writing spans everywhere
- Give agents live access to traces and logs while developing
