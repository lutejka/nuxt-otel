## No traces in DevTools

Check these in order:

1. **Tracing channels are enabled.** `tracingChannel` is opt-in. Set `tracingChannel: true`, or use an object and set the channels you need to `true`.
2. **DevTools are enabled.** `nuxtOtel.devtools` must not be `false`.
3. **You loaded a page after starting the dev server.** The panel only shows telemetry collected during the current session.
4. **You are running a development server.** The DevTools panel is not available in production builds.
5. **You are using a Node.js preset.** The built-in SDK is Node.js-only. On other presets, set `instrument: false` and provide your own SDK.

If you configured only some channels, remember that an object enables every channel that is not explicitly set to `false`.

## Some channels are missing

- Check the minimum Nuxt version for each channel in [Traced Events](/reference/traced-events).
- Confirm the channel is not set to `false` in `tracingChannel`.
- Remember that `nuxt.*` channels require Nuxt `>= 4.5.0`, while `h3`, `srvx`, and `unstorage` require Nuxt `>= 5.0.0`.

## MCP server shows disabled

The MCP endpoint is mounted only when the optional `@devframes/agentic` peer is installed:

```bash [pnpm]
pnpm add -D @devframes/agentic
```

Restart the dev server after installing it. If the endpoint still shows `disabled`, confirm the package is in your project’s `devDependencies` and that `nuxtOtel.devtools` is enabled.

## MCP requests are rejected

Devframe rejects requests without a matching `Origin` header. Set `Origin` to the exact dev server origin, including the scheme and port:

```json [mcp.json]
{
  "mcp": {
    "nuxt-otel": {
      "type": "remote",
      "url": "http://localhost:3000/__opentelemetry/__mcp",
      "headers": {
        "Origin": "http://localhost:3000"
      }
    }
  }
}
```

## Custom SDK does not reach DevTools

- Set `nuxtOtel.instrument: false` so the built-in SDK does not compete with your SDK.
- Point the exporter at `{devServerUrl}/__opentelemetry-ingest` or the full signal URL.
- Call `sdk.shutdown()` when the server closes so buffered telemetry is flushed.
- Confirm the exporter uses OTLP HTTP rather than gRPC.

See [DevTools](/guide/devtools#forward-custom-instrumentation-to-devtools) and [Instrumentation](/guide/instrumentation) for complete examples.

## No traces in production

The DevTools panel is development-only. In production, configure your OTLP exporter with `OTEL_EXPORTER_OTLP_ENDPOINT` or the exporter options in your custom SDK. See the [Configuration Reference](/reference/configuration-reference#environment-variables).
