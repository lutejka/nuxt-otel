## Module options

Configure these under `nuxtOtel` in `nuxt.config.ts`.

| Option       | Type      | Default | Description                                                         |
| ------------ | --------- | ------- | ------------------------------------------------------------------- |
| `instrument` | `boolean` | `true`  | Adds the built-in `NodeSDK` (intended for Node.js presets)          |
| `devtools`   | `boolean` | `true`  | Adds the OpenTelemetry panel to Vite DevTools in development        |

## Tracing channels

`tracingChannel` is a top-level Nuxt option, not a `nuxtOtel` option. All channels are disabled by default.

| Channel     | Type      | Default | Minimum Nuxt | Traces                                           |
| ----------- | --------- | ------- | ------------ | ------------------------------------------------ |
| `nuxt`      | `boolean` | `false` | `4.5.0`      | SSR renders, islands, data fetching, and plugins |
| `h3`        | `boolean` | `false` | `5.0.0`      | HTTP requests handled by h3                      |
| `srvx`      | `boolean` | `false` | `5.0.0`      | Server requests and middleware                   |
| `unstorage` | `boolean` | `false` | `5.0.0`      | Storage operations                               |

Accepted values:

- `false` or unset — disable every channel
- `true` — enable every channel
- An object — enable every channel that is not explicitly set to `false`

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  tracingChannel: {
    nuxt: true,
    h3: true,
    srvx: false,
    unstorage: false,
  },
})
```

## Environment variables

The built-in SDK reads the standard [OpenTelemetry environment variables](https://opentelemetry.io/docs/specs/otel/configuration/sdk-environment-variables/):

| Variable                      | Description                                                |
| ----------------------------- | ---------------------------------------------------------- |
| `OTEL_SERVICE_NAME`           | Service name reported by the SDK                           |
| `OTEL_TRACES_EXPORTER`        | Trace exporter (`otlp`, `console`, `none`)                 |
| `OTEL_METRICS_EXPORTER`       | Metrics exporter (`otlp`, `console`, `prometheus`, `none`) |
| `OTEL_LOGS_EXPORTER`          | Logs exporter (`otlp`, `console`, `none`)                  |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Collector base URL; the SDK appends the signal path        |
| `OTEL_EXPORTER_OTLP_HEADERS`  | Comma-separated `key=value` headers sent to the collector  |

## DevTools ingest endpoint

In development, custom SDKs can send telemetry to the DevTools panel through these OTLP HTTP endpoints:

| Signal  | URL                                                    |
| ------- | ------------------------------------------------------ |
| Traces  | `{devServerUrl}/__opentelemetry-ingest/v1/traces`      |
| Logs    | `{devServerUrl}/__opentelemetry-ingest/v1/logs`        |
| Metrics | `{devServerUrl}/__opentelemetry-ingest/v1/metrics`     |

You can also set `OTEL_EXPORTER_OTLP_ENDPOINT` to `{devServerUrl}/__opentelemetry-ingest` and let the exporter append the signal path.

## Example configuration

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lutejka/nuxt-otel'],
  tracingChannel: {
    nuxt: true,
    h3: true,
    srvx: false,
    unstorage: false,
  },
  nuxtOtel: {
    instrument: true,
    devtools: true,
  },
})
```
